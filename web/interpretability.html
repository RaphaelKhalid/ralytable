Where the codes live

Three layers in, snap to a code, three layers out.

A dense transformer's middle is a continuous vector you can only interrogate by training probes against it. Replace that vector with a nearest-neighbour lookup into a fixed table and the middle becomes a symbol — a thing with an index, a frequency, and a list of everything it has ever fired on. That is the entire trick, and it is what makes the rest of this page possible.

DiscreteCore character-level · 6.4M parameters · 6 layers · 6000 steps
Quantisation is EMA vector-quantisation in a 32-dimensional projected space, with dead-code revival. 1015 of 1024 codes are live on the corpus — the bottleneck is being used, not collapsed.

Read this before the pretty parts

The model cannot reason. That is not the point.

This is a 6.4M-parameter character model trained for six minutes on 4,042 synthetic word problems. It writes fluent, perfectly-formatted nonsense. Here is an unedited sample from the very checkpoint this page analyses, at temperature 0.7:

codes1024.pt prompt: "[1] A train travels" · temperature 0.7 · unedited
loading…
A train travels 120 miles and the time taken is 2.5 hours, so the speed is 6 minutes = 60 × 60 = 6/3 hours, and the answer is 7.5. Every quantity is wrong. Every citation is right. Step [3] cites [1] and [2]; step [4] cites [3]; no step ever cites one that does not exist; no premise pretends to cite. Form is learned long before content — which is exactly the pathology this project exists to fix, reproduced inside our own architecture.

The claim is legibility, not capability.

You cannot open a dense 6.4M model and read off what its middle layer is doing. You can open this one and list all 1015 things it can be doing, with counts. Whether the thing being done is good is a separate question, and here the answer is plainly no.

Role purity, against its own null

The legibility proxy: for each code, how well does it predict whether its character sits in a premise, a derived step, or the answer? The majority class is 58% of the corpus, so a codebook carrying no role information at all still scores 0.580.

The honest answer

Mostly, the codes are surface character classes.

Having looked at all 1015 live codes: this alphabet is largely orthographic. The median code puts 63% of its firings on a single character, and 326 codes are a single character outright. The rest are character classes — one code for "a digit inside an arithmetic expression", another for "a consonant in the middle of a word" — conditioned on where in the line they occur.

That also explains most of the +0.086 role excess, and it is worth being blunt about. The codes that predict role best predict it because the surface string gives the role away:

How much of it is the character? The right control is not "could a codebook with no information score this", it is "could you score this without the codebook at all". You largely can, because the format leaks the label. Predicting the role from the raw character alone, no model involved:

majority class0.5801—
the character alone, 140 of them0.6314+0.051
the 1024 codes0.6640+0.084

So 61% of the excess was the character, not the code. The codes beat the raw character by +0.033. That is the honest number, and it is real, because a code sees context and can separate the same character in a premise from one in a derived step. It is a third of what the headline sounded like. Reproduce it with experiments/06_discrete_core/leakage.py.

So is the legibility fake?

No, but it is smaller than "0.664 role purity" sounds. A code that fires on ] genuinely does predict "derived step", and it is genuinely nameable — you can write "citation bracket" on it and be right every time. That is real interpretability. It is just interpretability about format, and this model has learned format and nothing else, exactly as its generated samples show.

What would falsify it

The test that matters is whether the structure is load-bearing: change premise [1], and step [3]'s codes should change. If they do not, the citation is decorative and the codebook is describing a typesetting convention. That experiment has not been run yet. It is the next one.

Limitations that apply to every number above

  • —One seed, one corpus, one teacher. No error bars.
  • —The corpus is synthetic and formulaic, which almost certainly makes this structure far easier to encode than real text.
  • —Role purity is a three-class proxy for legibility. "A code predicts a role" is much less than "a human can name what a code means".
  • —Codes are read at positions with at least 128 characters of left context, so this measures the model mid-sequence, not at a cold start.
  • —The dense baseline has no bottleneck rather than a matched continuous one, so some of the gap is regularisation, not discreteness.

Reproduce it

Every number on this page comes out of one script.

export_viz.py loads the checkpoint, forwards the corpus, and writes the JSON this page fetches. No hand-entered figures, no cached summary — if you retrain, the page changes.

shell
python experiments/06_discrete_core/sample.py       # trains codes=1024, writes codes1024.pt (~6 min, GPU)
python experiments/06_discrete_core/export_viz.py   # writes site/codebook.json and web/codebook.json
