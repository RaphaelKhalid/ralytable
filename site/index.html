A compiler that knows what a vector holds.

PyTorch sees a list of numbers and checks that the shapes line up. It cannot know that a vector is a bag already holding 7 things with room for 31 more — so overstuffing it throws nothing, crashes nothing, and just quietly makes the model worse.

Raly puts that in the type. Overstuff it, and it does not compile.

The type

One annotation, three things a tensor throws away.

Vec[Concepts; load 3; roles {Subject, Verb, Object}]
  • ConceptsWhich space. That fixes the VSA family, the dimension and the codebook — atoms of a different codebook are noise here.
  • load 3How full it is, against a capacity the checker derives from the space. Superposition load is counted, not hoped for.
  • roles {…}Which roles are bound in is static. What is bound to them stays runtime.

How it works

Four phases, one run, every error at once.

raly check runs every phase every time. No phase returns a Result; each returns a value plus diagnostics, so a syntax error does not silence name resolution and an unresolved name does not silence the type checker.

sourcea .raly file
→
lextotal: any bytes yield tokens, and never a panic
→
parserecursive descent that recovers; the tree covers the whole input
→
resolvetwo namespaces, scopes, a DefId for every reference
→
typecheckfour properties, four small decidable solvers

dimension — abelian-group unification (Kennedy's units of measure), so a mismatch prints a concrete residual rather than "unification failed"
VSA family — a finite enum; MAP[1024] and FHRR[1024] stop being the same type
capacity / load — natural-number intervals over measured capacity: bundle adds, bind multiplies, cleanup collapses to one
role schema — row polymorphism with scoped labels (Leijen); unbinding a role a closed row does not carry will not compile

Why a compiler is the right shape

If the type knows which roles a vector carries, the signature is the documentation.

You can read what a function represents without running it, without a probe, and without an archaeology pass over trained weights. That is the second half of the pitch, and it is the half that made this a language rather than a library.

Interpretable-by-construction is not a new field — concept bottleneck models, weight-sparse transformers and KANs all exist. Compile-time dimension checking is not new either; Dex, Futhark and F# have had it for years. Two narrower claims are what is left: interpretability living in the type system, and that no ML tool people actually use has checks like these.

What works today

The front end is done. The back end is not.

Nothing on the "not built" list is stubbed or half-written. It is absent. A project pitched on catching what other tools hide should not begin by hiding what it has not built.

  • ✓Diagnostics — byte-offset spans, primary and secondary labels, separate note: and help: channels, stable greppable codes, output asserted character-for-character.
  • ✓Lexer — total: any input, including arbitrary bytes, yields a token stream and never panics.
  • ✓Parser — hand-written recursive descent with error recovery; the tree is total over the input.
  • ✓Name resolution — two namespaces, scopes, use-before-definition as its own diagnostic, suggestions that err towards silence.
  • ✓Type system — all four properties: dimension, VSA family, capacity/load, role schema. 179 tests, zero warnings.
  • ✓Browser playground — the real Rust compiler as wasm, 102KB. Live errors and inline squiggles, no install.
  • ·IR and codegen — do not exist. raly cannot produce an executable and does not pretend to.
  • ·The model — Ralytable-1 is not built. What exists is a 6.4M-parameter toy whose citation structure is flawless and which cannot reason.

Measured, not cited

The numbers in the compiler came out of experiments in this repo.

Kill criteria were written before the runs, every headline number was re-derived independently, and several results are negative — which is the point rather than an embarrassment.

04 · capacity

31 items at D=1000.

Roughly 3× what a literature summary implied. This is the number the checker prints, reproduced exactly at four measured points and interpolated between them.

experiments/04 →
07 · retrieval cost

Averaging chunks costs a quarter of retrieval accuracy.

On BEIR scifact, mean-pooling 8 passages into one document vector drops hit-rate from .877 to .619 with realistic grouping — and 70–76% of that is the averaging itself, not the coarser granularity. mpnet has twice MiniLM's nominal dimension and the same cost: nominal D predicts nothing.

experiments/07 →
06 · discrete core

A discrete bottleneck costs about 3 points of accuracy.

At matched parameters, and it buys 8 points of role legibility above chance. Cross-entropy actually improves. Bigger alphabets got more capable and more legible together, the opposite of the tradeoff expected. One datapoint at toy scale, not a curve.

experiments/06 →
01 · claimed vs causal

A model's account of its own reasoning is not the causal graph.

Every graph-derived predictor correlates with measured causal importance at |ρ| ≤ 0.09; raw position correlates at −0.45. Structure has to be built in, not requested.
